## 1. 原最终判定代码的问题与最小修改方案

`scripts/run_completed.py:98–106` 取得 `answer['result']`，仅验证其为 Python bool，随后 True→keep、False→filter。`decision_basis` 只反映有没有 solver 事件，并非六项证据核验。
原作者函数在 `patches/completed_function_bodies.py:175` 发现模型文字 `Not satisfied` 时还能提前返回 False。旧 runner 对可行结果要求至少一个成功 SMT，但对过滤没有对称要求：没有强制 UNSAT、定位精度、变量身份、条件来源或宏语义检查。

`completion/metrics.py` 没有发现算术翻转：执行失败仍是未分类，不算过滤成功。但它没有 UNKNOWN 的明确保留动作，也无法区分“告警保留”与“明确判为 keep”。因此保留它作为历史基线，新增单独指标函数。

最小实现为：**保留原候选结果 → 新判定层检查 → 输出 FILTER / KEEP / UNKNOWN 与 action → 新指标汇总。** 本轮只在新离线入口接入，不重构原路径分析，也不通过改标签消除错误。

## 2. 六项过滤条件：能核验什么、缺什么

| FILTER 条件 | 本轮能够实现的机械检查 | 仍缺的可靠证据 |
|---|---|---|
| 1. 目标位置准确 | 原告警与保存 frame 的变量、代码、目标文本对应；正文 SHA-256；目标文本唯一性 | 原工程精确源码版本、函数起始行与绝对行号一致性；重复目标不能只凭文本消歧 |
| 2. 控制及提前退出条件正确 | 提取字段是否存在；引用已知提取错误审计，出现问题阻断过滤 | 分支/循环/goto 的完整性和支配关系；当前没有通用的 C 控制流证明 |
| 3. 身份、类型、赋值和传参一致 | 已知变量身份异常阻断过滤；复核记录绑定实际代码 | SSA、别名、指针重赋值、跨过程值关系及宏展开；参数名相同并不证明值语义正确 |
| 4. 约束语义及来源可信 | FILTER 要求逐断言对应精确公式、代码片段行号与哈希；六项独立复核均完整 | 机器不能自动证明任意 LLM 约束等价于 C；需要真实人工或可信分析器复核，不能靠模型自称正确 |
| 5. 有效且来自已检查约束的 UNSAT | 重放最后决定性 SMT2；校验结果、feasible 布尔及候选判定一致；UNKNOWN/错误/无断言拒绝 | 只重放公式不证明源码语义；因此仍须与第 1–4 项的完整复核绑定 |
| 6. 无关键缺失或异常 | 原执行状态、错误、已知审计异常、缺日志、错误/歧义 SMT 等；已发生修复的历史单独提示 | 无报错不证明上下文充分；缺宏定义、关键函数和赋值路径仍须独立确认 |

规则如下：

1. 未完成原执行、关键记录缺失、格式异常、已知未解决问题、目标歧义、求解异常或输出与求解不一致 → UNKNOWN，action=KEEP。
2. 一致的 SAT 候选可以输出 KEEP，含义仅为继续保留告警，并不宣称真实缺陷成立。第 1–4 项尚待复核的状态随记录保留，不会据此批准过滤。
3. UNSAT 候选只在六项均满足、独立复核绑定完整且没有硬错误时输出 FILTER。否则 UNKNOWN、action=KEEP。
4. 单凭 LLM 文字、一个 False、一个 UNSAT 或六个布尔勾选，均不足以过滤。
5. 复核必须绑定整体 evidence SHA、精确 query SHA、源码片段 SHA、行号、全部断言公式/索引/来源、复核者/方式和未解决事项。任一缺失、错配或过期都拒绝；合成复核不能批准真实 benchmark。

第 5 点检查的是**复核记录的完整性和绑定关系**，不是验证任意 C 程序语义的证明检查器。人工/可信分析器的语义判断仍是信任前提。本轮没有伪造任何真实样本的完整复核记录，因此未批准真实样本 FILTER。
