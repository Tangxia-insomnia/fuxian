## 1. 结论

1. **在明确受限的结构化子集内，可以检查保留契约。**B、Δ 与 Final 被转为声明/断言 IR，能发现成员缺失、字面 SMT 身份映射缺口、sort 冲突、重复项及新建 Solver 后的丢失；域外输入明确 UNKNOWN。不能由此证明公式等价、完整 C 语义或路径结果。
2. **成功检出 A04 的历史问题。**U10 输入缺 2 条基础断言和 2 项声明；U01 修复仍缺这些成员，出现未经映射的新符号；U09 虽恢复基础成员，完整输入比较仍发现 object 的 Int/BitVec 冲突和新增成员丢失。
3. **符号身份只按可核实的字面证据检查。**能拒绝 object→object_ptr/object_bv 的无映射替代，不能推断它们究竟是不是同一 C 对象。
4. **A01 没有被错误标为安全。**其最终脚本可以静态保留 PASS，同时其 U10 接收输入有丢失、全链 FAIL；极性正确性明确 NOT_ASSESSED，仍引用 E01 的历史问题，不改 E01、不删矛盾断言。
5. **没有进入算法修复。**下一步最小方案另立实验：只修 B/Δ 的显式传递与保留契约，保持原模板和安全门槛；当前报告不实施它。

## 3. 实现范围与冻结

独立新增 [checker.py](checker.py)；核心区域为 S-expression 解析、类型化 term 读取、SMT-LIB IR、历史 Z3Py AST IR、`check_contract`。不导入任何历史项目模块，不 eval/exec 输入，也不调用求解器。额外 runner/test/config 和完整输入输出都只在 E02。

保留检查采用**结构成员存在**，不是逻辑等价：例如 `(= x 0)` 与 `(= 0 x)` 不自动视为同一断言。重复断言不要求相同倍数，但计数并保留原文。每条 IR 包含输入引用、哈希和命令序号/代码行号；来源是模型记录/脚本，不冒充独立 C 源码断言证明。

## 7. 覆盖边界与未完成部分

检查器支持的是限定语法，不是完整 SMT-LIB/Z3Py/C 解析器。数组、量词、动态函数、普通 If/循环、push/pop、求解假设参数、复杂符号拼写及不支持的返回协议会给 UNKNOWN。某些看似可静态识别的输入仍无法匹配；没有为覆盖率降低门槛。

字面 symbol+sort 和逐行输入来源不能证明 C 变量身份、类型宽度、宏语义或跨函数状态正确；不同形式的等价断言可能被保守报告为结构缺失。基础公式本身可能极性错误；基础保留不会使其正确。重复同类型声明可被记录但不代表可执行 SMT 合法。模型返回的布尔值、真实求解结果及完整程序路径均未验证。

UNKNOWN 是静态诊断状态，和安全策略 UNKNOWN 无调用关系；本轮没有产出 FILTER/KEEP/UNKNOWN 安全裁决。历史 N/A/不完整样本留在分母中，没有被删除。
