## 1. 审计结论与数据价值

原数据具有实际价值：真实C项目的告警位置、较多函数体/上下文、部分标签及控制条件，足以支持来源归一、程序片段分析、困难案例研究和分层实验。现有确定性模块已经实现受限调用、值版本、返回、写入、路径组合及内存桥，不需要重写。

缺口集中在**正式实验集身份/标签口径、真实程序证据生产及逐约束语义绑定**。JSON字段封装能够解决格式和来源问题，不能恢复不存在的原构建和调用状态。本轮没有把E08单样本的缺失扩大成“所有材料毫无价值”，也没有把可读代码当成现成的SMT证明。

最短可行研究路径是：保留原数据和原标签 → 来源封装/候选清单 → 一个明确假设的纯标量片段合同 → 有限C整数约束编码/诊断 → 单独报告局部结果，完整告警继续UNKNOWN。这个受限实验不会绕过R01–R05的真实证据门槛，也不等同于最终技术路线已贯通。

## 2. 本轮确认的事实

### 2.1 数据口径尚未完整对齐

本轮全量解析冻结benchmark的14个JSON，共1,017条记录；UBI/UUA两文件字节相同，排除此文件别名后有954条记录出现。原二元标签记录424条（0:385，1:39），另有-1四条、缺标签526条；这不是告警去重后的全新官方集。

README声称443条、47个真缺陷。当前不能构建一个有充分来源的行级manifest精确恢复这个口径。尤其Cppcheck Linux原文件594条，只有68条有标签且无result=1；统计图83(8)，metrics却是68/3。不能将缺失标签、-1或方法输出补成真值。OpenSSL CodeQL及部分baseline输出也存在数量/标签口径差异。

完整路径、计数、原字段出现率、文件SHA及相关结果结构见 `dataset_inventory.md`。本轮仅观察，不裁定作者标签错误，不清洗或替换原实验集。

### 2.2 能直接复用与不能直接复用的内容

可直接保留：原标签值、源码/告警原文、保存的路径/行号元数据。可确定性适配：文件hash/JSON Pointer、保留原ID的来源限定别名、不同代码载荷字段的显式选择、原B/Δ脚本来源引用。

需可信提取：函数/调用声明身份、参数转换和transfer、ValueVersion、返回绑定、对象和MemoryVersion、路径与逐约束绑定。原始TU/编译上下文、规范rule ID及部分原标签缺失，不能由Adapter补造。详见 `R01_R05_field_mapping.json`；其中DIRECT仅指指定事实可复用，不表示语义就绪。

### 2.3 B/Δ 足以保存结构，不足以认证语义

冻结benchmark没有完整typed B/Δ表。官方流水线运行时用模型生成B/Δ，B还含缺陷查询谓词。项目E03已保留原响应、哈希、代码和合并区间；E02已有静态结构检查。这些能力应复用。

但原Z3符号/排序不等于C声明/类型，脚本行不等于C行，旧条件未绑定当前值/内存版本和frame/path，结构PASS不能直接授权求解结果用于告警过滤。详细九项审计与语义边界见 `SMT_constraint_audit.md`。

### 2.4 当前真实证据准入限制必须如实保留

R01–R04现有入口只批准`synthetic-self-contained`范围；R05 `src/protocol/evidence_runtime.py:29` 对非fixture生产者固定UNKNOWN。它们目前不是接上真实源码就自动认可的通用编译数据库分析器。

因此“Adapter能调用旧模块/保留报告”与“Adapter能产生真实PASS”是两个不同承诺。后者不能在不讨论认证入口的情况下保证实现。不能伪装合成TU或fixture来获得PASS。若未来确需扩展真实证据准入，应单独批准兼容性研究，复用旧算法，不重写R01–R05；本轮不做此事。

已有R05最新扩展协议包含MemoryVersion→ValueVersion桥及嵌套生命周期检查，不需再次实现同一机制。R05-0历史文档中的草案/缺口描述不能替代当前协议事实。保存历史30条仍UNKNOWN、完整/部分已验证路径0，不能把合成测试或初轮结构验证PASS当作真实覆盖。

## 4. 建议的统一来源层

这是设计要求，不是已开发Schema或Adapter：

- 用原文件路径/哈希、JSON Pointer、原row/index定位记录；保留已有sample_id。无既有sample_id的类别才新增来源限定别名，并标明它不是原数据字段。
- 将标签/告警元数据、原源码载荷、原条件、旧模型公式、确定性证据分开引用。不得以同名字段的值互相替代。
- 每项关系有原记录引用、源码hash/范围、身份绑定依据、适用路径、状态和缺失项。源C、脚本、派生文本、构建上下文使用不同hash域；原字符/字节/行坐标单位明确。
- 对旧R01–R04记录保留原ID和命名空间；新R05引用只在有证明的对照关系上连接，不重建旧版本ID、不按变量名称归并。未知路径/对象不能生成空快照伪装完整性。
- SMT单独登记查询义务、逐符号C类型/版本、前提范围和来源、definedness。局部结果与最终告警裁决分开；SAT/UNSAT/UNKNOWN与FILTER不是同一状态域。

这些要求可由独立派生目录承担，不需改变原benchmark或现有安全门槛。当前只读映射文件并非新代码接口。
