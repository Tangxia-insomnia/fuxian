`semantics.py:49` 的 `Source` 使用保存的完整函数体绑定函数、词法作用域、声明偏移/行号、C 类型、表达式结构和 body SHA-256。`p`、`*p`、`p->len`、`p->data` 获得不同结构身份；未知成员定义仍为 UNKNOWN。仅接受可识别的基础类型、struct 指针和显式全局简单成员声明，不推测 typedef 或指针别名。

`semantics.py:304` 的 `check_polarity` 复用 E01 的 C 标量条件规范化，对 `p`、`!p`、`!!p`、零比较、括号和重复否定进行局部核对。对生成的单变量零测试及 `Not/And/Or` 使用零/非零两值真值表，不使用 SMT。分支相反、恒真弱化、恒假候选均拒绝；不同符号、未知方向或不支持表达式诊断 UNKNOWN。不得把针对另一个变量的空指针缺陷假设当成路径条件。

`Source.guard` 只确认简单分支及紧邻无条件 return 后的假边。宏、复杂条件、goto/break/continue、插入语句、复杂 CFG 不推测。历史复杂函数即使局部可读，完整上下文仍未验证。整数和指针的 Int 仅可用于零测试，Bool 用 Bool；这不批准普通地址算术、整数宽度或溢出语义。

`semantics.py:346` 的 `check_mappings` 拒绝不同源码对象合并到同一 SMT 符号、显式 C 类别与 SMT sort 冲突。一个对象拆分/改名但关系未证明，返回 UNKNOWN。状态变化、地址逃逸、别名和跨函数标志均阻止局部结果被当成完整验证。

`semantics.py:388` 的成员混淆检查只比较简单 `+/-` 赋值与模型等式的完整形状。仅当源成员被其指针根替代、其余形状一致时报告局部身份破坏；不推断赋值的时序、可达性或成员的缺失类型。

原 E02/E03 B+Δ 检查单独运行，结果未放宽；本层不改变任何输入断言，不接入生产 pipeline，不提供自动 FILTER 权限。诊断 `PASS/REJECT/UNKNOWN` 是约束候选检查状态，`alert_safety_decision` 始终为 null。

### E04-ND

数据：`codeql_linux` position=23，sample_id=`NPD/codeql/kernel69:row=23:index=42`，目标帧 `__ip6_append_data`。原 `selected_source.c` SHA-256：`4f652c2800b05d4fab8cf926af60a66c348cbdd8e5cc95f2620555feaf1e20a9`。

1. **U02 恒真弱化已检出**：源码一基第 271 行 `if (fraggap)`，目标第 275 行处于真边，应要求非零。真实 U02 为 `Or(fraggap == 0, fraggap != 0)`，两值表为 `[true,true]`，预期为 `[false,true]`，报告 `tautological_branch_weakening`。原记录/模型注释的 270 与实际 271 分别保留。
2. **U06 成员身份混淆已检出**：源码第 176 行 `fraggap = skb->len - maxfraglen;`，模型为 `fraggap == skb - maxfraglen`。其余减法结构相同，成员叶子被指针根替换，报告 `pointer_member_identity_collapse`。指针 `skb` 来自第 11 行显式声明，`fraggap` 第 170 行为 unsigned int。没有补造成员定义；`skb->len` 的具体类型仍缺失。
3. 原 E03/E02 对 U10 输出仍为 **结构 PASS**，新增 E05 局部检查为 REJECT。此例直接说明结构保留与源码语义正确是两项不同检查。
4. U02 原响应 SHA-256 `beff74bf8da49808fb5577082e033e25a93e957dc73fa51a800253364ac99cd3`；U06 `2400bd4f63661a904b52a137651a0c86eb4239e95ac5432e98169aae23bc3c69`。原响应没有编辑、重写或重新调用模型。

不能据此证明 fraggap 的状态从赋值点传播到目标、skb 的重分配或 unsigned 减法正确；这些限制与局部错误诊断同时保留。
