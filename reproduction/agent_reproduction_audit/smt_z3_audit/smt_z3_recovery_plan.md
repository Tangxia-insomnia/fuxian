## 2. 建议下一次最小实验

建议名称 `E02_base_constraint_preservation_static`，仅作为计划，当前未创建该目录或代码。

1. 固定候选前 Git 状态与 SHA-256，原 Prompt、原 pipeline、安全 v1、E01 全部保持不动。
2. 第一轮只做“基础约束与新增约束的输入/输出保留契约”，不运行 Z3、不调用模型、不改变量推理和宏处理。
3. 使用通用合成 B/Δ，覆盖空 Δ、只有注释、合法新增、重复断言、符号重声明、sort 冲突、函数中创建新 Solver、修复脚本丢旧断言。存在不透明控制流时不擅自执行或认定保留。
4. 对照 A04 缓存链：识别 B 未交给 U10，识别 `object_ptr` 不能替代原符号；对照 A01：保留检查不能掩盖已知极性错误，不能删掉矛盾断言。
5. 不追求本轮过滤数量变化；只能报告静态保留/冲突/不适用及原因，不能将静态检查通过称为路径不可行。
6. 候选与合成/10 条调试结果冻结后，再对固定 20 条回归集做一次同样的静态检查；不得逐样本调整后再次使用该集声称独立验证。

静态断言对比只能证明受限表示下的保留关系；不能用文本匹配宣称逻辑等价，也不能自行替换作者模板。若需要表达式规范化，支持子集和拒绝策略必须单独写清。

## 4. 将来恢复求解时的证据契约

拟保留：dataset_id/position、告警和源码哈希、P 的已证实前提与缺失项、原始条件与分支、符号身份/类型、B/Δ/合并脚本、每条断言的来源及否定理由、修复前后差异、实际求解公式/假设/三态/耗时，以及检索失败和迭代终止原因。这是本项目建议，**不是论文已公开的 JSON schema**。

现有安全 v1 仅在获得完整 evidence bundle 后才可单独调用，并且调用会重放 Z3；应在后续明确授权的求解阶段执行。其六项条件和绑定独立语义复核要求不降低；E01 的局部通过不能替代任意一项。未来也不能让 U04 的自然语言 `Not satisfied` 直接驱动最终过滤。

## 5. 评价与停止条件

每个未来实验分别报告静态检查覆盖率、拒绝/不适用原因、基础断言丢失数、极性冲突数、符号冲突数和耗时。真正进入裁决阶段后，再报告 FILTER/KEEP/UNKNOWN、真实缺陷操作保留率、误删率、误报过滤率和证据完整性；UNKNOWN 永不计过滤成功，操作保留不等于证明缺陷成立。

出现输入哈希变化、修改保护文件、意外模型调用、未经授权求解、自动删除矛盾断言、证据不完整被批准过滤或按样本 ID 特判时停止，保留失败材料。当前只完成审计文档，到此不进入 E02、R02/R03 或全量实验。
